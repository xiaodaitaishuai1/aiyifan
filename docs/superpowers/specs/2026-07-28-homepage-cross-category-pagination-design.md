# 首页跨分类补齐与分页设计

## 目标

首页在横幅之后至少展示六张两列卡片，即首批总数至少七条；用户上滑到底部时继续追加更多去重影片。

## 数据规则

- 不增加网络接口或分页参数，复用已经缓存的首页各分类影片。
- 当前选中分类的影片始终排在最前面。
- 其余首页分类按现有分类顺序作为补齐来源，并按 `mediaKey` 去重。
- 首批展示补齐序列的前七条；其中第一条仍是横幅，余下六条是两列卡片。
- 每次触底追加六条；没有未展示影片时不再追加。

## 状态与交互

- 首次加载、切换分类和下拉刷新均重新生成去重序列，并回到首批七条。
- RecyclerView 仅在不能继续向下滚动、当前未加载且仍有更多影片时加载下一批。
- 分页只改变已展示数量，不重新请求网络；现有网络异常和回退数据逻辑保持不变。
- 若所有分类去重后仍少于七条，则展示全部可用影片且停止加载更多。

## 实现边界

- 新增纯 Kotlin 分页模型，负责跨分类排序、去重、初始切片与下一页切片。
- `HomeFragment` 收集各分类列表并驱动分页模型；`HomeVideoAdapter` 与横幅/两列卡片资源不改变。
- 热门页、搜索页和数据接口协议不在本次改动范围内。

## 验证

- JUnit 覆盖当前分类优先、跨分类去重、首批七条、每批六条、无更多数据和刷新重置。
- 运行全量测试、Debug 构建、Lint，并在 Pixel 6 真机验证首次展示和触底追加。
