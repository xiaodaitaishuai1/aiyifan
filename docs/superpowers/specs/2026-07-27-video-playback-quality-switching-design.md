# 视频播放清晰度切换设计

## 目标

为 `VideoPlayerActivity` 增加与原 APK 一致的清晰度切换能力。用户仅在全屏播放器中选择当前视频可用的清晰度；切换地址后保留播放位置和播放状态。

选择仅在当前播放器会话内生效：同一视频切换后续剧集时沿用，退出或重新进入播放器后不再保留。

## 现有基础

- `VideoDetail.qualities` 已表示接口提供的清晰度档位。
- `Episode.resolution` 会传入 `CatalogRepository.resolvePlayback`，远端仓库据此向播放接口请求目标播放地址。
- `VideoPlaybackController.prepare` 已支持以指定位置重新准备媒体并开始播放。
- 原 APK 的清晰度入口位于横屏播放器控制区，选择列表显示可用档位和当前选中状态。

## 交互

仅当处于全屏模式且存在至少两个可用清晰度时，在播放器覆盖层显示当前清晰度标签，例如 `1080P`。点击后显示可用档位列表，当前项以选中状态标记。

选择其他档位后关闭列表并开始切换。切换成功后显示短提示；失败后显示失败提示，继续使用原清晰度。竖屏和应用内小窗不显示该入口。

## 状态与数据流

`VideoPlayerActivity` 持有本次播放会话的已选 `resolution`，不使用 `SharedPreferences` 或其他持久化存储。

首次播放和每次切集的档位选择按以下顺序决定：

1. 当前会话已选择的档位，前提是目标剧集支持它。
2. 接口标记为默认的档位。
3. 当前剧集声明的档位。
4. 第一个可用档位。

活动页以选中的 `resolution` 构造待解析的 `Episode`，再调用 `CatalogRepository.resolvePlayback`。解析得到可播放地址后，交给 `VideoPlaybackController.prepare`。

切换清晰度时记录当前播放位置和 `isPlaying` 状态。新地址准备成功后定位到记录位置，并恢复原播放或暂停状态。会话内切集时复用已选档位；若目标集不提供该档位，则选择其默认可用档位并更新会话状态。

## 失败处理

- 没有两个有效档位时隐藏入口，不提供无效切换。
- 目标档位没有可播放地址、解析请求失败或播放器准备失败时，恢复旧档位、旧媒体地址、旧进度及原播放状态。
- 无法恢复旧媒体时显示现有播放源加载失败提示，避免错误地显示切换成功。

## 结构

- `feature/video` 新增纯 Kotlin 的清晰度选择策略，负责从可用档位和会话选择中确定目标档位。
- `VideoPlayerActivity` 负责全屏入口、弹出菜单、会话状态、异步解析以及恢复 UI。
- `VideoPlaybackController` 增加必要的明确操作，以便在重新准备媒体后恢复暂停状态，而不让 Activity 直接操作播放器引擎。
- 继续复用现有 `PlaybackQuality`、`Episode`、`CatalogRepository` 和 Media3 播放链路，不改变远端接口协议。

## 测试

- 单元测试覆盖初始档位优先级、会话选择跨剧集沿用，以及目标剧集缺少已选档位时的回退。
- 播放控制器测试覆盖切换后恢复播放位置和暂停状态。
- 资源/布局测试覆盖全屏清晰度入口及其默认隐藏状态。
- 实现完成后运行 `./gradlew.bat test`、`./gradlew.bat lint` 与 `./gradlew.bat assembleDebug`。

## 非目标

- 不将选择写入持久化存储，不在重新进入播放器后恢复。
- 不增加 VIP 档位限制、下载清晰度、语言或字幕切换。
- 不修改远端 API 或伪造接口未返回的清晰度。
